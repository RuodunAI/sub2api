# 0.1.290 控制台会话（Valkey `s2s_` 令牌）：单向发布

> 0.1.290 是一个发布单元（0099–0101），从线上 0.1.288 直接升级，0.1.289 没有单独发布。升级顺序、备份和回退的完整步骤见 `0.1.290-release.md`；本文只讲会话部分。

从本版本起，控制台登录只签发 `s2s_` 会话令牌，会话存放在 Valkey（设计见 CONTRACTS §100）。JWT 的签发与校验、`POST /auth/refresh` 和刷新令牌都已删除。迁移 `0101_drop_jwt_sessions.sql` 删除 `refresh_tokens`、`login_sessions`、`auth_flows` 三张表。

**这是单向发布：没有反向脚本，回到上一版只能从数据库备份恢复。**

## 发布的影响

- **所有人重新登录。** 上一版签发的 JWT 与刷新令牌全部失效：控制台下一次请求得到 401，直接回到登录页。访问密钥（`sak_`）不受影响。
- **Valkey 是登录的前提。** 会话、两步登录与二次验证的流程都只在 Valkey；Valkey 不可用时登录与控制台请求返回 503（不是 401，控制台不会被登出），恢复后照常。
- **新核心不再读取的环境变量：** `SUB2API_JWT_SECRET`、`SUB2API_ACCESS_TOKEN_TTL`、`SUB2API_REFRESH_TOKEN_TTL`。**`SUB2API_JWT_SECRET` 不要删**：0.1.288 核心启动时要求它（至少 32 字节），回退或升级计划没走完时重启的旧核心都要用原来的值。网关外壳与核心分开升级，所以外壳仍把这三个传给核心（`legacyCoreEnv`，只有 0.1.290 之前的核心读取），各 compose 模板、`.env.example` 和 `ovh/prepare.sh` 也保留 `SUB2API_JWT_SECRET`；先升外壳或 compose、后升核心都可以。等不再支持回退到 0.1.290 之前，再在之后的版本一起删除。会话时长由 `SUB2API_SESSION_IDLE_TTL`（默认 168h）和 `SUB2API_SESSION_MAX_TTL`（默认 720h）决定。

## 发布步骤

**新版本启动之前，旧核心必须全部停止。** 上一版节点读写被删的三张表，新旧节点混跑时旧节点的登录、换发和二次验证会报错。步骤见 `0.1.290-release.md` 第三节：

- **网关托管（线上）**：在建升级计划之前备份数据库，然后照常建计划。`primary-first-v1` 先停掉所有从节点的核心，主节点最后进入维护、停机后才迁移并启动新版本（`deploy/gateway/README.md`），本身满足“先全停”。
- **非托管（`deploy/single`、直接运行核心的多节点部署）**：停掉每个节点，确认没有上一版核心在跑，备份数据库，再启动新版本；第一个节点启动时执行迁移 0099–0101。

数据库备份是唯一的回退途径。

发布后核对：

```sql
SELECT id FROM schema_migrations WHERE id = '0101_drop_jwt_sessions.sql';                          -- 一行
SELECT to_regclass('refresh_tokens'), to_regclass('login_sessions'), to_regclass('auth_flows');   -- 都是 NULL
```

用超管登录一次，`POST /api/v1/auth/login` 返回的 `access_token` 以 `s2s_` 开头。

## 回退

网关拒绝跨 schema 回退（`sub2api-gateway rollback` 和建计划都会拒绝），托管核心见到不认识的迁移也拒绝启动。回到 0.1.288 的唯一办法是**从发布前的备份恢复数据库**，完整步骤见 `0.1.290-release.md` 第五节。与会话有关的是：

1. 停掉所有核心节点。
2. 从发布前的备份恢复数据库。
3. 确认 `.env` 里还有原来的 `SUB2API_JWT_SECRET`（删了就恢复原值）。网关外壳会把它传给核心，`deploy/single` 和网关的 compose 也照旧映射它，不用再配 `core_env_inherit`。
4. 启动 0.1.288 核心。备份之后在新版本里发生的写入全部丢失；Valkey 里的 `s2a:sess:*`、`s2a:usess:*`、`s2a:sid:*`、`s2a:flow:*` 上一版不读，留着无害，到期自动消失。所有人再重新登录一次。

线上出问题首选**修复前进**（下一个核心版本，新迁移接在 0101 之后）。
