# 0.1.290 控制台会话（Valkey 不透明令牌）的回退

> 版本号 0.1.290 是候选值，发布时改成真实版本（文件名与本文一起改）。

本版本没有迁移（设计见 CONTRACTS §100）。签发哪种登录凭证由开关 `session.issue` 决定：`jwt`（默认）或 `s2s`。所有节点都同时认 JWT 与 `s2s_`，所以回退只是把开关切回 `jwt`。

## 首选：切开关

`PUT /settings/session {"issue":"jwt"}`（超管本人，二次验证 `session.issue`），广播后各节点立即改为签发 JWT。已签发的 `s2s_` 会话照常有效到过期或被撤销；新的登录、换发拿到 JWT。切回 `jwt` 不检查节点版本；切到 `s2s` 时，只要还有存活节点不支持不透明会话（心跳里没有能力标记 `session.s2s`），接口返回 409 并在 `details.nodes` 列出这些节点。

## 接口不可用时的两条应急路径

1. **直接改库**（全部节点，不用重启）：

   ```sql
   INSERT INTO settings (key, value) VALUES ('session', '{"issue":"jwt"}')
   ON CONFLICT (key) DO UPDATE SET value = settings.value || '{"issue":"jwt"}', updated_at = now();
   ```

   不经总线广播：每个节点最多缓存开关 30 秒（`issueCacheTTL`），**30 秒内**全部改为签发 JWT。之后照常可以用 `PUT /settings/session` 切换。
2. **环境变量固定单个节点**：给节点设 `SUB2API_SESSION_ISSUE=jwt` 并**重启**该节点，它从此不读设置（`GET /settings/session` 的 `source` 为 `env`）。去掉变量再重启才恢复跟随设置。
   - 直接运行核心或 `deploy/single`：写进核心进程的环境（`deploy/single` 写进 `.env`，`compose.yml` 已映射）。
   - 网关托管的核心：设在网关进程的环境里即可（变量在网关传给核心的白名单 `inheritedEnv` 里），或写进网关配置的 `core_env`；改完重启网关托管的核心。

## 回退代码到上一版

上一版只认 JWT：`s2s_` 会话的用户收到 401，需要重新登录；Valkey 里的会话与流程留着无害，到期自动消失。先按上一节切回 `jwt` 并等现有 `s2s_` 会话自然减少，可以减小影响面。
