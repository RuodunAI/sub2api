# 插件包不再依赖主节点：每个节点留一份，缺包时从任意在线节点取

2026-11-18。分支 `feat/fv2-pkgstore`（基于 `feat/forwarding-v2`）。**已实现**。

所有者的决定：“每个节点都要安装，保留插件吧?”；更早的：“我们这个是多节点架构但是并不需要做分布式一致性”。

## 1. 现状（按代码核实）

插件包按 sha256 寻址，不在 PG（迁移 0022 起）。托管部署下包存在**每个节点网关**的状态卷 `<root>/plugin-blobs/<前两位>/<sha256>`（`gateway/internal/pluginblob`），核心经本机管理 socket `GET/PUT /system/plugin-blobs/<sha256>` 存取（`server/internal/plugin/blobs.Shell`）；没有网关时是核心本机目录，只支持单节点。

- **写**：核心的 `install.Upload` 先 `Put` 再写版本行。上传、市场安装（安装节点也存一份）、内置插件导入（持 `plugins:builtin` 锁的那个核心）都走这条路。网关先写本机，**再推到主节点**（`PUT /internal/plugin-blobs/`，节点范围 `plugin-upload`，只许从节点 → 主节点），主节点确认后才返回。主节点不在时，从节点上的上传、市场安装、内置导入全部失败。
- **读**：本机缺包时网关 `pull`：**先问主节点**（读不到主节点行就直接报错；本机就是主节点时直接 404，不问别人），主节点没有或失败，再逐个问 `NodesWithPackage` 给出的全部启用节点（不看是否存活）。节点间读（`GET /internal/plugin-blobs/`，范围 `plugin-artifact`）已经允许任意两个启用节点之间进行，只限被某个版本引用的摘要。
- 市场版本：每个节点按 `package_url` 自己下载，失败或摘要不符才走上面的存储。
- 取到的包留在本机网关的存储里；网关每 10 分钟删掉不被任何版本引用、超过 1 小时的包。

与任务描述的出入：从其它节点取包的回退已经有了（2026-11-05），新节点和丢了缓存的节点在主节点宕机时**能**从别的节点取到包（只是先白白连一次主节点）；真正依赖主节点的是**写入**（推主节点）和“主节点自己缺包不问别人”。另外，真实三节点测试里“主节点宕机时新节点 d 起不来”卡在**核心发布包**（`core-artifact` 只从主节点取），那是核心程序分发，不属于插件包，本次不改。

## 2. 改成什么

- **写只落本机**：网关把包写进自己的存储就返回，不再推主节点。删除 `PUT /internal/plugin-blobs/`、节点范围 `plugin-upload`、每个来源节点 2 个并发上传的限制和发送端的 `push`。
- **读问在线节点**：本机缺包时，逐个问其它“启用且心跳新鲜”的节点（`Node.Fresh`，复用现有的存活判断，不新加时长），第一个给出正确摘要的胜出；对方 404 表示它没有。某个节点给的字节摘要不符或请求出错，记下来继续问下一个。主节点不再特殊。
- **谁有包**：不登记。在线节点逐个问一遍（没有就是一个 404），不加表、不加节点间协议、不做注册中心。
- **每个节点留一份**：本机上传、取过的包都留在本机存储里，GC 规则不变（只删未被引用的），所以装过某版本的节点都持有它的包，任何一个在线就能供给其它节点。

## 3. 失败时的表现

- 所有在线节点都回答没有：网关 404，正文写明问过哪些节点、哪些节点离线没问；核心得到 `blobs.ErrNotFound`（带这段原因）。审查、同意接口照旧返回 410 `package_gone`（文案改为“没有在线节点持有这个安装包：让持有它的节点恢复在线，或重新上传”）；节点加载失败的错误文本带上原因，节点页可见。
- 有节点出错（连不上、摘要不符）且没有节点给出正确的包：网关 502，错误逐个列出；不当作“包不存在”。
- 摘要不符的字节不落盘（`Store.Write` 校验后才改名）。

## 4. 升级与旧数据

- 无核心迁移（预留的编号 0112 没有用）。没有表变化。
- 旧主节点上已有的全部包原地保留，它和其它节点一样被问到、供给包。
- 只改网关二进制和核心的错误文案。网关滚动更新期间：旧网关节点上的上传仍要推主节点，主节点换成新网关后不再接受推送（403），那段时间在旧网关节点上上传会失败；旧网关的主节点自己缺包时不问别人，取不到在新网关节点上传的包。换完网关再上传、启用即可；旧网关取包（主节点 → 全部启用节点）能取到新网关节点上的包。

## 5. 取舍

- 上传后、别的节点取走之前，包只在接到上传的那个节点上；它永久丢失就要重新上传。所有者已接受“持有该包的节点都不在线时装不了”。
- 心跳新鲜但实际刚宕机的节点会被问到一次，连接失败后继续问下一个；心跳不新鲜的节点不问，列在原因里。
